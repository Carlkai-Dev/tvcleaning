# TCL 85C755: G08 / V643 preservation-only compatibility notes

Checked on a real TV on 2026-10-20. The goal was to replace the home screen
while retaining the installed apps and their enabled states. No package was
disabled, uninstalled or cleared, and no several-day debloat regression test
was performed. This is **not a tested debloat list**.

The launcher/controller used for the compatibility tests was a modified build
derived from upstream `42288ae4a4aa25339c2478074249231a4a6ebab6`, not the
unmodified current reference launcher. The controller-assisted recovery
described below is not functionality supplied by this device note.

The reported **app ABIs** are 32-bit; this is not a claim that the physical
processor is 32-bit. Do not choose an arm64-only APK from the chipset name.

`Smart TV Pro`, `G08` and `G08_4K_GB` are not unique retail-model identifiers.
The existing [C755 example](../../examples/tcl-c755-google-tv/debloat.txt)
describes a 75-inch Australian unit with similar build identifiers. This
85-inch preservation-only test does not validate that example's package
disable choices, or establish compatibility for every C755/G08 firmware.

## Launcher and Live TV identities

- Stock HOME:
  `com.google.android.apps.tv.launcherx/com.google.android.apps.tv.launcherx.home.HomeActivity`.
- Live TV / HDMI player:
  `com.tcl.tv/com.tcl.player.TVActivity`.

Keep the player distinct from the TV-input services. No tuner/input service,
stock launcher, setup/recovery package, casting service or firmware updater
was disabled during this test. Their individual functionality is not all
certified merely because the packages remained enabled.

## A successful Home-role command did not change the resolver

On this build, HOME candidates reported these priorities:

- Google TV `HomeActivity`: **2**.
- setupwraith `RecoveryActivity`: **1**.
- The tested third-party launcher's HOME activity: **0**.
- Settings `FallbackHome`: **-1000**.

An Android HOME-role change was accepted, but resolving HOME and pressing
Home still opened Google TV. A nonzero HOME intent-filter priority in the
test APK was also reported as 0 by the device; it was not a working fix.
Verify the resolved component and the actual Home action rather than
treating a successful role setter as proof.

Read-only checks in the TV's authorized ADB shell:

```sh
getprop ro.product.model
getprop ro.product.device
getprop ro.software.version_id
cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME
```

The stock Google TV and setupwraith packages remained enabled. No
package-disable workaround was tested on this unit.

## Accessibility redirection has two full-reboot caveats

A custom, explicitly enabled helper redirected only the stock Google TV
Home window, without screen-content retrieval or key-event filtering.
The firmware's default HOME component still remained Google TV; successful
redirection must not be described as a native default-launcher change.

1. A full reboot retained the helper in `enabled_accessibility_services`
   but reset `accessibility_enabled` to `0`. Restoring the master flag alone
   left the selected service **unbound**.
2. The system log reported `[TclAppBoot]:forbid bind service` for the helper.
   Opening the launcher normally during that boot, then refreshing only its
   owned accessibility entry, allowed the service to bind. The observed
   `ACCESS_RESTRICTED_SETTINGS: allow` app-op did not by itself remove this
   TCL startup restriction.

Check an actual service process and binder connection, not only the selected
service list or master flag. For the helper being diagnosed:

```sh
settings get global boot_count
settings get secure enabled_accessibility_services
settings get secure accessibility_enabled
dumpsys activity services YOUR_LAUNCHER_PACKAGE/YOUR_ACCESSIBILITY_SERVICE
```

The successful test used an authorized external controller to recover only
after Android startup, opening the launcher only if the awake TV was already
on Home. It preserved other accessibility entries and verified a live process
with `hasBound=true`. It did not interrupt a media app, Settings, an input or
standby. No vendor auto-start app-op, broad secure-settings grant, root or
firmware modification was used.

This recovery depends on that controller being available after a full TV
reboot. Once bound, the helper handled subsequent Home events locally.
Rebinding on every app return is unnecessary; the tested helper tracked boot
changes rather than reopening Home on every service rebind.

## Validation limits and safe rollback

- Injected D-pad directions and OK reached apps in the dock and lower grid.
  App launch is not proof of playback, subscriptions or login behavior.
- Injected Android Home events returned from Settings and a media app.
  A full reboot then recovered Home and the helper's actual binder without
  manual accessibility repair during that successful cycle.
  This used `adb reboot`, not an unplug/replug cold-start test.
- Restoring stock Home and the prior accessibility master/selection state
  was exercised. All originally installed packages stayed enabled.
- Physical-remote button confirmation, every dedicated remote key, casting,
  RF reception, external HDMI picture/audio and several-day stability were
  not independently established by these checks.

For an accessibility-based setup, stop/remove only the owned redirect before
restoring stock Home; changing the HOME role alone can leave redirection
active. Preserve other accessibility services and the recorded original
state. Do not copy another device's disable list or clear app data to force
a handover.

Network ADB is authorized maintenance access. Do not expose port 5555 through
the router. Disabling debugging also prevents a controller-dependent boot
recovery from running; account for that dependency rather than claiming the
launcher alone makes this firmware reboot-stable.
