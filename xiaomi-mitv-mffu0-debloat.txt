# Everything is DISABLED, not uninstalled.

# Tested 2026-10-21 on a real unit: all 15 packages reached `disabled-user`, the accessibility
# list and HOME resolution were unchanged, and no new entries appeared in the crash buffer.
# Not yet verified across a reboot or over days — treat that as pending.
#
# Notes from this TV:
# - This unit is NOT running the stock launcher as Home. It runs Aerial (app.orchard.tv,
#   github.com/pengchujin/aerial-tv), which does NOT claim MAIN+HOME. It takes over the Home key
#   at runtime through an AccessibilityService (HomeGuardService), so `cmd package resolve-activity
#   -a android.intent.action.MAIN -c android.intent.category.HOME` still returns
#   com.mitv.tvhome/.MainActivityUserMode. That is expected, not a failure. Do not "fix" it by
#   disabling com.mitv.tvhome — if the accessibility service ever stops, Home falls through to
#   FallbackHome and you get a black screen.
# - enabled_accessibility_services on this unit is
#   com.xiaomi.voicecontrol/.VoiceAccessibilityService:app.orchard.tv/app.orchard.tv.guard.HomeGuardService
#   ⇒ com.xiaomi.voicecontrol must stay ENABLED. It looks like an assistant package but it owns the
#   accessibility entry that Aerial's HomeGuard shares the list with.
# - Wireless ADB is on port 5555 the whole time (service.adb.tcp.port=5555, ro.adb.secure=0), and it
#   survives standby. The pure-Python client works here: tools/tv.py needs adb_shell + pyasn1 + rsa.
# - The shell here is zsh: unquoted variables are NOT word-split, so a list like
#   `for p in $PKGS; do echo "pm disable-user --user 0 $p"; done` emits ONE line with every package
#   in it and pm silently acts on the first only. Use a literal list, or bash.
