# Xiaomi TV A Pro 75" 2026 (MiTV-MZTU0, codename river, MediaTek), Google TV / Android 14 (SDK 34),
# firmware UKN1.240806.017.V816.0.25.3.10.URTMIXM. Likely a good start for other 2024+ Xiaomi Google TVs.
# Live TV app: com.mitv.livetv (set it as live_tv_package and hide it in launcher config.xml).
# Stock launcher: com.google.android.apps.tv.launcherx (pass it to restore.sh and build-and-install.sh:
#   STOCK_LAUNCHER=com.google.android.apps.tv.launcherx launcher/build-and-install.sh).
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/xiaomi-tv-a-pro-2026/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/xiaomi-tv-a-pro-2026/debloat.txt com.google.android.apps.tv.launcherx
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Keep (TV needs them): mitv.service and com.mitv.overseaservice (remote keys, Netflix button, BT remote),
# com.mediatek.* (extservice, tv.agent, tis, tuners, airplay), com.mitv.livetv, com.mi.bluetooth,
# com.mitv.setup, com.xiaomi.android.tvsetup.partnercustomizer, com.xiaomi.mitv.scenemode (game mode).
# Already disabled at the factory: com.xiaomi.floatingframe, com.iwedia.tvinput, atsc/isdb tuners.
# Default IME is Gboard, no keyboard quirk. 1.8 GB RAM.
#
# Google TV 14 quirk (the important one): HOME is resolved by intent priority here and the saved
# "default home" is ignored. launcherx has priority 2, the setup wizard's RecoveryActivity priority 1,
# a sideloaded launcher 0. Disable launcherx alone and Home lands on RecoveryActivity, which
# crash-loops system_server (soft reboots every ~60 s, Wi-Fi drops). Shell may not disable that one
# activity, so the whole setup wizard package is disabled below; it is only used for first-time setup.
# Re-enable it (and launcherx) before a factory reset or to get the Google home back: restore.sh does.
# The firmware re-enables com.netflix.ninja by itself (Netflix button), so don't bother disabling it.
#
# ---- Launcher extras tested on this model (contributed by @nikhiltalreja, GitHub) ----
# Checked on a real set on 2026-10-20, firmware UKN1.240806.017.V816.0.26.5.6.5.URTMIXM.
#
# Bluetooth pill: the launcher has a Bluetooth button next to Inputs. It lists bonded accessories
# first, then a row for the TV's own Bluetooth screen (remotes and other accessories), then devices
# from its own scan, pairing inline. This firmware's settings scanner finds devices in the radio
# stack but never lists them, so the pill is the working path. Grant both permissions after every
# reinstall (build-and-install does this for you):
#   adb shell pm grant com.gathin.tvhome android.permission.BLUETOOTH_CONNECT
#   adb shell pm grant com.gathin.tvhome android.permission.BLUETOOTH_SCAN
# Set bluetooth_speaker_name/address in config.xml so the fallback row opens your buds' Connect /
# Disconnect / Unpair page instead of the scanner.
#
# Remote hotkeys: with launcherx disabled the YouTube button (KEYCODE_BUTTON_3) has no handler, and
# the LIV button (KEYCODE_BUTTON_8) still deep-links SonyLIV through the vendor service. Enable the
# launcher's accessibility service and map both in config.xml key_remaps:
#   settings put secure enabled_accessibility_services com.gathin.tvhome/.HomeKeyService
#   settings put secure accessibility_enabled 1
#   KEYCODE_BUTTON_3=com.google.android.youtube.tv
#   KEYCODE_BUTTON_8=com.apple.atve.androidtv.appletv
# Home here is KEYCODE_HOME and works once launcherx is gone; KEYCODE_ALL_APPS is not involved.
# The mappings are model-specific: key_remaps is empty by default, so leave it empty if your remote
# sends different keycodes.
